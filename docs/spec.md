# ETBS Scheduled Slider 仕様（r2・2026-10-18）

`etbsjp/etbs-scheduled-slider`。VK Blocks のスライダーを、1枚ごとの表示期間つきで管理画面から差し替えられるようにするプラグイン。
最初の導入先は www.neogate.jp のトップのメインスライダー。

## 0. この文書の扱い

- 決定事項（§1）は、ユーザーが確認済み。変えるときはユーザーに確かめる
- §2 以降は実装の仕様。実装で仕様と違う形にしたときは、PR でこの文書も直す
- r1 のレビュー（UX・コード・リリース可否の3人。結果は3人とも FAIL）で出た指摘は、この r2 に反映済み

## 1. 決定事項

| # | 項目 | 決定 |
|---|---|---|
| D1 | 目的 | スライドの差し替えをブロックの編集なしでできるようにし、1枚ごとに表示開始・表示終了の日時を持たせて、時刻どおりに出し入れする |
| D2 | 見た目と動き | VK Blocks（無料版でよい）のスライダーと同じ HTML を出す。動きと CSS は VK Blocks に任せる。Swiper を自前で持たない |
| D3 | 時刻での切り替え | 表示開始前のスライドは HTML に一切出さない。cron は使わず、ページキャッシュ（LiteSpeed Cache）の保存期間を「次の切替時刻まで」にして切り替える |
| D4 | 複数のスライダー | 1サイトに複数のスライダーを作れる。スライダーごとに「ひな形」と動きの設定を持ち、ブロックでどのスライダーを出すかを選ぶ |
| D5 | ひな形 | 1枚の画像の枚数と HTML は「ひな形」で決まる。本体には VK の普通のスライダー項目と同じ形の「画像1枚＋リンク」を入れる。サイト固有のひな形は、そのサイトの mu-plugin から登録する |
| D6 | 表示開始日時 | 必須。「今すぐ表示する」ボタンで今の日時を入れられる。保存するとその場で表示に出る場合だけ、確認のダイアログを出す |
| D7 | 表示中のスライドが検査に通らないとき | 変更を保存せず、古い値のまま表示を続けて、何が足りないかを知らせる。送信前に JS でも止める。表示中でないものは下書きに落として知らせる |
| D8 | 少ないとき | 0 枚: 何も出さず、一覧の上で 0 枚になる時間帯を事前に警告する。1 枚: ループ・自動送り・ドットを止める。ループに足りない枚数（§5.4）: サーバ側で繰り返して足りる枚数にし、見た目を保つ（ドットは増える） |
| D9 | 権限 | 既定は `edit_pages`（編集者以上）。`etss_capability` フィルタで変えられる |
| D10 | 日時プレビュー | ログイン中で権限のある人だけに「この日時の並び」を見せる。URL は手で打たせず、編集画面と一覧に「この時刻の表示を見る」リンクを置く。フロントには「プレビュー中」の帯を出す。下書きも含めて確かめられる |
| D11 | 移し替え | 既存の VK スライダーのブロックから、スライドを作る WP-CLI コマンドを持つ |
| D12 | 配り方 | public repo・ブランチは `dist` 一本・PUC で配る。文言は日本語で直接書く（readme.txt は置かない。etbs-notice-banner と同じ） |

## 2. データ

### 2.1 スライダー（`etss_slider`）

- 投稿タイプ。`public => false`, `show_ui => true`, `show_in_rest => false`, `supports => title`
- タイトル ＝ スライダーの名前（管理用。例「トップ」）
- メタ
  - `_etss_template`：ひな形の ID（既定 `vk-image`）
  - `_etss_options`：動きの設定（配列）。項目と既定値は VK のスライダーのブロックに合わせる
    - `autoPlay` true / `autoPlayStop` true / `autoPlayDelay` 2500 / `pagination` bullets / `loop` true / `effect` slide / `speed` 300
    - `slidesPerViewMobile` 1 / `slidesPerViewTablet` 1 / `slidesPerViewPC` 1 / `slidesPerGroup` one-by-one / `centeredSlides` false / `width` ''
  - `_etss_extra_class`：外枠に足す class（任意。サイトの追加 CSS に合わせるため）

### 2.2 スライド（`etss_slide`）

- 投稿タイプ。`public => false`, `show_ui => true`, `show_in_rest => false`, `supports => title, page-attributes`
  - クラシックエディタにする。ブロックエディタだと保存が2リクエストになり、メタボックスの値が消えるため（ECG 1.2.1 で踏んだ）
- タイトル ＝ 画像の代替テキスト（告知文）。必須
- `menu_order` ＝ 表示順（小さい順。同じなら表示開始の新しい順）
- 状態: `publish` と `draft` だけを使う。WP の予約投稿（`future`）は使わない。予約投稿は WP-Cron で公開に切り替わるので、D3 で避けた cron に戻ってしまうため
- メタ（すべて単一値）

| キー | 中身 | 必須 |
|---|---|---|
| `_etss_slider_id` | 属するスライダーの ID | ○ |
| `_etss_images` | ひな形の画像枠 ID → 添付ファイル ID の配列 | ひな形の定義による |
| `_etss_url` | リンク先。`/` で始まるサイト内のパスか、`http(s)://`。`//` で始まるものは弾く | ○ |
| `_etss_start` | 表示開始（UTC の Unix 秒） | ○（D6） |
| `_etss_end` | 表示終了（UTC の Unix 秒。0 ＝ 終了なし） | |
| `_etss_last_errors` | 前回の保存で出たエラー（表示用の一時状態） | |

- 表示の判定: `start <= now < end`（終了時刻ちょうどには出さない）。開始が 0 以下（未設定・不正）、終了が負の値（不正）のときは出さない
- 次の切替時刻: 開始・終了のうち、いまより**後**のものの最小。切替時刻ちょうど（= now）は「切り替わった」ものとして数えない
- 日時の入力はサイトのタイムゾーンで受け、保存の前に UTC 秒に直す。2000年より前・存在しない日付（2月30日など）・夏時間で存在しない時刻は形式エラーにする。秒つき（`…T12:00:30`）も受け付ける。夏時間の秋の重複時刻（NY の 2026-11-01T01:30 は2回ある）は、先の方（夏時間側）に解決する
- メタは `register_post_meta()` で型つきで登録する（REST には出さない。`_` 始まりの保護されたメタのまま）。キーの置き場は `ETSS_Meta` の定数1か所

## 3. ひな形（D5）

- `etss_register_templates` アクションの中で `etss_register_template( string $id, array $args )` を呼んで登録する
- 登録時に定義を検査する（`ETSS_Templates::normalize()`。WP に依存せず PHPUnit で確かめる）。誤りがあれば登録せず、`_doing_it_wrong()` で知らせて `false` を返す。同じ ID の二重登録も同じ（先のものを守る）
  - ID（ひな形・画像枠）は英小文字・数字・ハイフン・アンダースコアで、英小文字か数字から始める
- `$args`
  - `label`：管理画面に出す名前（必須）
  - `slots`：画像枠の配列（1つ以上、必須）。枠 ID ごとに次を持つ（並びが編集画面の並び）。「枠 ID => 定義」の形のほか、定義に `id` を持たせた並びの形でも渡せる（後者は ID の重複を検出できる。重複はエラー）
    - `label`（例「横長（PC・タブレット）」。必須）
    - `description`（見分ける手がかり。例「NEW の文字が無い版」。既定は空）
    - `required`（bool。既定 false）
    - `ratio`（想定の縦横比＝横÷縦の正の数。外れたら警告。既定 null）
    - `preview_dim`（プレビューに暗幕をかけるか。既定 false）
  - `render_item`：`callable( array $slide, array $context ): string`。スライド1枚の**中身**の HTML を返す。外側の `swiper-slide` の div は本体が付ける
    - 描画を作る #4 までは省略できる（本体の `vk-image` も #4 で足す）。指定したなら呼び出せる値でなければならない。#4 で、描画の時点で `render_item` が無いひな形は何も出さないようにする
    - `$context` には `index`（0 始まり）と `is_first` を入れる
    - `is_first` は LCP 用。1枚目の目に見える画像は `loading` を付けない
  - `default_options`：このひな形で新しいスライダーを作ったときの動きの既定値。§2.1 の項目名だけを受け付ける（知らないキーは typo として登録を弾く）。本体の既定値に重ねて使う
  - `item_class`：`swiper-slide` の div に足す class（例 `vk_valign-center vk_slider_item-paddingLR-zero`）。英数字・ハイフン・アンダースコア・空白だけ
  - `import_item`：`callable( array $parsed ): array`。§8 の移行コマンドが、VK のスライダー項目1つを枠 ID → 添付ファイル ID に割り当てるときに使う。任意
- 本体のひな形 `vk-image`
  - 画像枠は1つ（必須）
  - VK のスライダー項目に画像ブロックを1つ置き、リンクを付けた形と同じ HTML を出す
- エスケープはひな形の責任とする。本体は返された HTML を `wp_kses_post` に通さない（VK の属性を落とさないため）。この点は CLAUDE.md に書く

## 4. 管理画面

### 4.1 メニュー

- 「スライダー」の下に「スライド」（一覧・新規）と「スライダー」（一覧・新規）を置く
  - 親のメニュー「スライダー」はスライドの投稿タイプ（`etss_slide`）が作る。スライダーの投稿タイプ（`etss_slider`）はその子（`show_in_menu` にスライドの一覧を指定）にする
  - 子の投稿タイプには WP が「追加」を作らないので、「スライダーを追加」は `add_submenu_page()` で足す
- 権限は D9 のとおり。`etss_capability` は投稿タイプの登録時（`init`）に1回読む。文字列でない・空の値は `edit_pages` に戻す。フィルターは登録（`init` の優先度 10）より前、つまり mu-plugin かプラグイン読み込み時（`plugins_loaded` まで）に付ける

### 4.2 スライダーの編集画面

- ひな形を選ぶ。スライドが1枚でもあるときは変えられない（画像枠が合わなくなるため）
- 動きの設定は §2.1 の項目を並べる
- 「このスライダーを置く」の説明に、ブロック名と、置いているページへのリンクを出す（`has_block` で探す）

### 4.3 スライドの編集画面

- スライダーを選ぶ（必須）。画像枠はそのスライダーのひな形から作る
  - 選び直したら、保存して再読み込みするまで画像枠は変えない（「保存すると画像枠が変わります」と出す）
- 画像枠ごとに次を置く
  - 選ぶ・変更・外すのボタン（名前は枠ごと。例「横長の画像を選ぶ」）
  - プレビュー。暗幕の指定があればかける
  - ファイル名と寸法
  - メディアの画面のタイトルも枠ごとに変える
- リンク先は placeholder を使わず、説明文に例を書く。保存後は「開いて確かめる」リンクを出す
- 表示開始（必須）・表示終了の欄
  - 欄の横に、24時間制・曜日・残り時間で書き戻す（例「→ 2026年11月6日（金）12:00 に表示開始・あと3日4時間」）。英語環境では datetime-local が12時間制になり、取り違えるため
  - 「今すぐ表示する」ボタン（D6）
  - 説明は行動で書く。例「この時刻になると表示から消えます。空欄なら消えません」
  - 「この時刻の表示を見る」リンク（D10）
- WP の公開ボックスの日時の編集（`#timestampdiv`・`.misc-pub-curtime`）は隠す。公開ボックスに「表示: 表示予定（11/06（金）12:00 から）」の1行を足す
- 言葉は WP の「公開」と分ける
  - 期間は「表示開始日時／表示終了日時」
  - 状態は「表示中／表示予定／表示終了／下書き」

### 4.4 保存時の検査

- 検査する項目
  - スライダー
  - ひな形の必須の画像枠
  - 同じ添付ファイルを2つの枠に入れていないか
  - リンク先
  - タイトル
  - 表示開始（必須）
  - 終了が開始より後か
- 警告だけ出して保存はするもの
  - 縦横比が想定から大きく外れている
- エラー文には欄の名前を入れる（「表示開始日時の形式が正しくありません」）
- 欄には `aria-invalid="true"` と `aria-describedby` でエラー文を結び付ける。上部のエラーの一覧の各項目は、その欄へのリンクにする
- 検査に通らなかったとき
  - 表示中のスライド（保存済みの値で表示中、D7）: 変更を保存しない。状態と古いメタを保ち、エラーを出す
  - それ以外: 下書きに落とし、エラーを出す
- 失敗したときは、WP の緑の「公開しました」を出さない
  - `redirect_post_location` で message を差し替える
  - `post_updated_messages` もスライド用に用意する
- 送信前の JS 検査
  - 必須項目が欠けていたら送信を止め、欄へフォーカスを移す
  - 保存するとその場で表示に出る場合（いま表示中でなく、開始が過去）は、確認のダイアログを出す（D6）
- 検査を通らない経路を塞ぐ
  - クイック編集は、スライドの行のアクションから外す
  - 一括編集からは、状態の変更を外す
  - それでも `etss_slide` が送信値なしで publish になる場合（nonce が無い）は、保存済みのメタで検査して下書きに落とす
  - `future` で来たら `publish` に直す（投稿日時は今）
- 検査は送信値・保存済みの値・現在時刻・タイムゾーンを引数で受け取る関数にする（PHPUnit で書けるように）。`validate()` の結果は1回の保存で使い回す

### 4.4.1 実装での補足（#2）

- 検査は、公開（`publish`・`future`）で保存しようとしたときだけエラーにする。「下書き保存」は検査に通らなくてよく、エラー（赤）は出さない。縦横比の警告と、次の「保存しなかった欄」の通知だけ出す
- 下書き保存で、入力があるのに使えない欄（形式が正しくないリンク先・表示開始日時・表示終了日時、表示終了が表示開始以前、見つからない画像・別の枠と同じ画像）は、黙って捨てない（#3）
  - 下書きは保存する。その欄だけは保存済みの値のまま保ち、打った値は欄に戻す
  - 黄色（`notice-warning`）の通知で伝える。欄ごとに、直し方を添えた文を一覧にし、各項目はその欄へのリンクにする。例「リンク先は形式が正しくないため、前に保存した値のままです。「/」か「https://」で始まる形で入力してください。」。見出しは「下書きを保存しました。保存していない欄があります。入力した値は欄に残しているので、直して、もう一度保存してください。」の1段落。WordPress の緑の「下書きを保存しました」は、重ならないよう外す（`message` を除く）
  - 表示開始・表示終了のどちらかを保存済みの値に戻した結果、終了が開始以前になるときは、終了を戻さず空にして「表示終了日時は、表示開始日時より前になるため外しました。…」と伝える（食い違った期間を保存しない）
  - 欄を空にしただけのときは対象外（消したい入力なので、そのまま消える）
  - 判定は `ETSS_Validator::validate_slide()` の `unsaved`、値の戻しは `ETSS_Validator::keep_saved_values()`
- メタを書くときは、値に `wp_slash()` を通す（`update_post_meta()` は slash を外すので、通さないと値の途中のバックスラッシュが欠ける）。保存済みのメタを戻す `restore_meta` も同じ
- エラー・警告・保存しなかった欄の通知は `_etss_last_errors`（`errors`・`warnings`・`unsaved`・`protected`・`input`）に残し、保存後の画面（`?etss_notice=1`）にだけ出す。下書きに落としたとき・変更を保存しなかったとき・保存しなかった欄があるときは、送信された入力を欄に戻す
- 失敗したとき・保存しなかった欄があるときは `redirect_post_location` で `message` を外す。`post_updated_messages` は「公開」を使わない言葉に差し替える
- 縦横比の警告は、想定から 15% を超えて外れたとき（`ETSS_Validator::RATIO_TOLERANCE`）
- 公開ボックス: 日時の編集（`#timestampdiv`・`.misc-pub-curtime`）を隠し、「表示: 〜」の1行を足す。ボタン「公開」は「表示に登録」にする。ステータスの行は WP のまま残し、「公開済み」は「表示に登録済み」と表示する。公開状態（非公開・パスワード）の行は隠し、サーバ側でも非公開は公開に、パスワードは空に直す（検査を通らずに公開できる経路になるため）
- スライダーの選択肢は「名前（ひな形名・#ID）」の形で出す（同じ名前を見分けるため）
- 変更を保存しなかったとき（D7）は、入力されたタイトルも欄に戻す（`title_edit_pre`）
- reject のときは、`meta_input` で書かれたメタも保存済みの値に戻す
- 「この時刻の表示を見る」リンクは、`etss_after_schedule_fields` アクションの位置に #5 が足す
- 入力欄の書き戻し（JS）は、サイトの時計の「いま」との差を単純に引いて出す（夏時間をまたぐ日時では、1時間ずれうる。保存後の画面は PHP で正確に出す）

### 4.5 スライドの一覧

- 列
  - サムネイル: 画像枠を小さく並べ、足りない枠は「⚠ 縦長なし」のように出す
  - 代替テキスト
  - スライダー
  - 状態: 理由つき。例「下書き（画像不足）」
  - 表示開始・表示終了: 「11/06（金）12:00」の形。表示予定には「あと3日」
  - 表示順
- 上の切り替え
  - 「表示中／表示予定／下書き／表示終了／すべて」に、件数を付けて差し替える
  - 既定は「表示終了以外」。並びは表示順
  - スライダーでの絞り込み
- 一覧の上の要約（スライダーごと）
  - 例「トップ: 表示中 9 枚／次の切り替え 11/06（金）12:00『○○』が表示開始」
  - 「この時刻の表示を見る」リンク
  - 警告
    - これから 0 枚になる時間帯
    - 表示開始日時があるのに下書きのもの

### 4.5.1 実装での補足（#3）

- 状態は WordPress の公開状態ではなく、表示期間で決める（`ETSS_Display::status()`）。`pending`・`private` は下書きと同じ扱い
- 上の切り替えは「表示終了以外（既定）／表示中／表示予定／下書き／表示終了／すべて」の6つ。既定の「表示終了以外」も、戻れるよう切り替えの1つとして出す。引数は `etss_state`（既定は付けない）。ゴミ箱は WordPress のものを残す
  - 件数は、絞り込み中のスライダーの分だけ数える。スライダーの絞り込みは `etss_slider`（スライドの新規追加で、スライダーを選んでおく引数と同じ）。一覧の上の「絞り込み」（プルダウン）で選ぶ
  - 絞り込み中は、一覧上部の要約と警告も、選んだスライダーの分だけにする（「すべて」のときは全スライダー分）
  - 状態は投稿のメタと現在時刻で決まるので、当てはまる投稿 ID を先に求めて `post__in` に渡す。並びは `ETSS_List::sort_rows()` の順（表示順 → 表示開始の新しい順 → ID の新しい順）。列の見出しで並び替えを指定したときはそちらに従う
  - 年月の絞り込みは出さない。タイトルの後ろの「— 下書き」は、状態の列が伝えるので出さない
- 列: サムネイル・代替テキスト（タイトル）・スライダー・状態・表示開始・表示終了・表示順。クイック編集は外したまま
  - サムネイルは、ひな形の画像枠の順に並べる。足りない枠は、必須なら「⚠ 縦長なし」（警告色）、必須でなければ「縦長なし」（控えめな色）
  - 状態: 下書きだけ理由を添える。保存時と同じ検査を保存済みの値にかけて、エラーの欄から作る（例「下書き（画像不足・リンク先なし）」。2つまで出し、残りは「…ほか1件」）。検査には通るが下書きのものは「下書き（表示に登録前）」。「表示中」だけ太字（色は足さない）
  - 表示開始・表示終了: 「11/06（金）12:00」の形（現在と年が違うときだけ頭に年）。表示予定の表示開始には、残りを「あと3日」「あと5時間」の形で添える。未設定は「未設定」、表示終了なしは「なし」
  - 状態の列は 11em にする。最長の語句（「（表示開始日時が不正・」など 11 字）がぴったり収まる幅。状態の文言は、折り返してよい位置（状態名の後・「・」の後・「…」の後）ごとに `white-space: nowrap` の span（`etss-status__part`）に分け、語句の途中では折り返さない（「（」「）」「・」「…」は隣の語句に付けて、行頭に単独で落ちないようにする。分ける処理は `ETSS_List_Admin::wrap_reasons()`）。他の列の幅（サムネイル 150px・スライダー 6em・表示順 5em など）で調整する
  - 783px 以上では表に最小幅 890px を付ける。783〜1100px 未満では画面全体が横にスクロールする（列どうしを重ねて潰さないため。表を包む枠に `overflow` を付けないのは、手前の float の横に押し込まれて幅が狭まるため）。782px 以下は WP 標準の縮小表示（非主要の列が隠れる）なので最小幅は付けない
  - 日時の列（表示開始・表示終了）は、1280px 未満では「11/06（金）」と「12:00」の 2 行にして幅（6.5em）を詰め、1280px 以上では 1 行（9em）にする
- 要約（スライダーごとに1行。ゴミ箱の一覧では出さない）
  - 例「トップ: 表示中 2 枚／次の切り替え 11/06（金）12:00（あと3日）『○○』が表示開始」。次の切り替えが無ければ「次の切り替えはありません」。同時に変わるものが複数あれば「（ほか1件）」
  - 次の切り替えと表示中の枚数に数えるのは、表示中・表示予定のスライドだけ（下書きの開始は数えない）
  - 「この時刻の表示を見る」リンクは、`etss_summary_row_actions` アクション（引数: スライダーの ID・次の切り替え時刻）の位置に #5 が足す
- 警告（黄色の通知。1項目につき1行）
  - 0 枚の時間帯: 表示中・表示予定のスライドで数え、いま 0 枚の場合も出す（`ETSS_List::zero_windows()`）。スライドが1枚も無いスライダーには出さない。各行に「スライドを追加」（そのスライダーを選んだ追加画面）のリンクを付ける
  - 表示開始日時があるのに下書き: 表示終了日時がすでに過ぎているものは除く。表示開始の早い順に3枚まで、「冬のキャンペーン（表示開始 10/23（金）22:23）」の形で、編集画面へのリンクにする。「編集画面で「表示に登録」を押すと、表示開始日時から表示されます。」の説明は、警告のまとまりの先頭に1回だけ出す
  - 0 枚の警告の「スライドを追加」には、`aria-label`（例「お知らせにスライドを追加」）を付ける
- 一覧の行が使う添付ファイル・スライダーは、`the_posts` で `_prime_post_caches()` に1回でまとめて読み込む
- 状態・件数・要約・0 枚の時間帯・並びの計算は、時刻と値を引数で受ける関数（`ETSS_List`・`ETSS_Display`）。画面への出力と読み出しは `ETSS_List_Admin`

## 5. 表示

### 5.1 ブロック `etss/slider`

- 動的ブロック。属性は `sliderId` だけ
- `supports`: `html: false`, `reusable: false`
- 編集画面ではスライダーを動かさない。枠に次を出す
  - スライダーの選択
  - 表示中の枚数と次の切り替え
  - スライドの一覧へのリンク
- `index.asset.php` を置き、依存のスクリプトを宣言する
- 翻訳は使わず、日本語で直接書く（D12）

### 5.2 VK との連携

- VK が使えるかは、`WP_Block_Type_Registry::get_instance()->is_registered( 'vk-blocks/slider' )` で判定する
  - ハンドル名では判定しない。管理画面ではハンドルが登録されないため、誤った警告が出る
- 描画は `render_block()` に `blockName => 'vk-blocks/slider'` と組み立てた HTML を渡す。VK のブロックとして描画させ、CSS と JS の読み込みを WP に任せる
  - 外枠: `wp-block-vk-blocks-slider swiper swiper-container vk_slider vk_slider_<blockId> etss-slider etss-slider-<ID> <extra_class>` と `data-vkb-slider`
  - `blockId` は `etss-<スライダーの ID>`
  - VK の JS は `.vk_slider_<blockId>` で Swiper を起動するので、class と blockId を必ず揃える
- ドットの位置と大きさなど、サイトの見た目の調整はひな形かサイトの CSS で行う。本体は CSS を持たない
- 描画の時点でも、保存時の検査と同じ必須項目を確かめ、欠けたスライドは出さない（多重の守り。検査を通らずに publish になった経路があっても、壊れたスライドを出さない）
- VK が無効なとき
  - ブロックは何も出さない
  - `etss` の目印を付け、nocache にする（壊れた状態を保存させないため）
  - 管理画面に知らせる

### 5.3 読み込み（LCP）

- 1枚目の目に見える画像には `loading` を付けず、`data-no-lazy="1"` を付ける
  - LiteSpeed Cache の画像の遅延読み込みが、1枚目を `data-src` に書き換えないようにするため
- それ以外は `loading="lazy"` にする
- これはひな形の責任とする。本体のひな形 `vk-image` はこのとおりにする。`fetchpriority` もひな形が決める

### 5.4 少ないとき（D8）

- ループに要る枚数 ＝ `ceil( 最大の slidesPerView )` ＋（`centeredSlides` で、その値が偶数なら 1）＋ `slidesPerGroup`（one-by-one なら 1。それ以外の `slides-per-view` は一度に見せる枚数＝ `ceil( 最大の slidesPerView )`）
  - 例: 1.3 枚見せ・中央寄せ → 2＋1＋1 ＝ 4
  - 最大の slidesPerView は、Mobile・Tablet・PC のうち最大。数値でない・0 以下・NaN・INF（`'1e999'` など）は 1 として扱い、上限 20 で打ち切る（1e9 でも繰り返しの枚数が膨らまない）。1 未満の正の値（0.5 など）は 1 枚見せの扱い
- ループが有効で、枚数が 2 以上かつ要る枚数未満なら、並びを繰り返して要る枚数以上にする（並び全体をそのまま繰り返すので、順番は保たれ、要る枚数を超えることがある）
- 1 枚なら `loop`・`autoPlay` を false、`pagination` を hide にする
- この計算は WP に依存しない関数にし、PHPUnit で確かめる

## 6. キャッシュ（D3）

- ブロックを出すとき
  1. そのスライダーの公開状態のスライドから、今より後の開始と終了の時刻のうち最も早いものを求める。終了済みは問い合わせの段階で外し、件数の上限は付けない
  2. あれば、`do_action( 'litespeed_control_set_ttl', min( 秒数, 上限 ) )` を呼ぶ
     - 上限は `etss_max_ttl` フィルタで、既定は `DAY_IN_SECONDS`
     - 上限が無いと、次の切替が30日後ならページが30日保存される（TTL はトップページの保存期間の設定より優先される）
     - 秒数は「次の切替時刻 − 現在時刻」で、+1 秒しない。上限が 1 未満の値で渡されたときは、無制限にせず 1 日に戻す（`ETSS_Schedule::cache_ttl()`）
  3. `do_action( 'litespeed_tag_add', 'etss' )` と `do_action( 'litespeed_tag_add', 'etss_<ID>' )` を呼ぶ
- スライドやスライダーを保存・ゴミ箱へ移動・復元・完全削除したとき: `do_action( 'litespeed_purge', 'etss_<ID>' )`
  - 自動下書きでは消さない
  - 削除は `deleted_post_etss_slide` などの、投稿タイプ付きのフックで拾う
- プラグインを停止するとき: `etss` を purge する
- LiteSpeed Cache が無効でも `do_action` は何もしないだけで、表示は正しい（保存されないので毎回作り直す）
- LSCWP 6.4.1 のソースで確認済み: 4つのフックは実在し、ブロックの描画中に呼んでも出力バッファを閉じるときにヘッダになる。前提は、LSCWP のバッファが一番外側で、途中で吐き出されないこと
- 検証は LSCWP のデバッグログで行う
  - `[Ctrl] X Cache_control TTL -> N` と `[Tag] Add etss` は、LiteSpeed のサーバでなくても API のフックから記録される
  - purge は `LITESPEED_ON` が無いと記録されない。`LITESPEED_ON` が定義されるのは `X-LSCACHE` があるとき・CLI のときだけ（LSCWP 6.4.1 で確認）
  - そのため Local では、Apache に `SetEnv X-LSCACHE on` を入れて `LITESPEED_ON` を立て、応答の `X-LiteSpeed-Purge`・`X-LiteSpeed-Tag` のヘッダとログで確かめる
  - 陽性対照は #1 で取った（LSCWP 7.9.1・Local ai-wp-demo）。**出た**: `do_action( 'litespeed_purge', 'etss' )` で、応答の `X-LiteSpeed-Purge: public,b3c_etss` とログ（`added _etss`）の両方が出る。`SetEnv X-LSCACHE on` を入れると `X-LiteSpeed-Cache-Control: public,max-age=<TTL>` も出る
    - `SetEnv` が無くても、7.9.1 では purge のヘッダとログが出た（6.4.1 のソースの読みと違う）。確かめる手順は `SetEnv` ありを正とする
    - 目印のヘッダは接頭辞つき（`X-LiteSpeed-Tag: b3c_etss,b3c_etss_1,…`）で、ログは `[Tag] Add --- etss`
    - CLI（WP-CLI でプラグインを停止）の purge は「CLI request, queue stored」としてログに残り、次の要求で実行される
  - hit/miss は Local では確かめられない。本物の hit/miss は導入先で確かめる

## 7. 日時プレビュー（D10）

- `?etss_at=2026-11-06T12:00` を付けると、権限のある人にはその時刻の並びを出す。プレビュー中は下書きも含める
- 時刻を読む関数・権限を見る関数・nocache を出す処理を分ける。`get_*` / `resolve_*` に副作用を持たせない
- プレビュー中のページは `litespeed_control_set_nocache` にする。フロントの上部に「プレビュー中: 11/06（金）12:00 の並び（下書きを含む）」の帯を出す
- TTL は実際の現在時刻で決める

## 8. 移行コマンド（D11）

- `wp etss import-vk-slider <post_id> --slider=<スライダーの ID> [--index=<何番目の VK スライダーか。既定 0>] [--start=<表示開始。既定は今>] [--dry-run]`
  - 指定した投稿の本文から `vk-blocks/slider` を探す
  - スライダー項目ごとに、次を取り出す
    - 画像（`wp-image-NNN` の class から添付ファイル ID）
    - 最初のリンク先
    - alt
  - ひな形の `import_item` で枠に割り当て、スライドを作る。`import_item` が無ければ、1枚目の画像を最初の枠に入れる
  - VK の `data-vkb-slider` の設定を、スライダーの動きの設定に写す（`--update-options` を付けたときだけ）
  - 表示順は元の並び
  - `--dry-run` は作らずに表で出す
  - 足りない枠・見つからない添付ファイルがあれば、その項目を下書きで作り、理由を出す

## 9. アンインストール

方針は etbs の配布プラグイン共通の案A。

| 分類 | 対象 | 扱い |
|---|---|---|
| 利用者が作ったコンテンツ | `etss_slider`・`etss_slide` の投稿とメタ | 残す |
| 一時状態 | `_etss_last_errors` | 消す（`delete_post_meta_by_key()`） |
| 自分が仕掛けた cron・オプション・独自テーブル | ― | 無し |

## 10. 配布と運用

- ヘッダ
  - `Requires at least: 6.3`（`apiVersion: 3` の下限）
  - `Requires PHP: 7.4`
  - `Author: ETBS (DAI)`、`Author URI: https://etbs.jp`
  - `Text Domain: etbs-scheduled-slider`
- 版数はヘッダの `Version:` の1か所だけ。CSS・JS の版は `get_file_data()` でヘッダから読む（etbs-notice-banner と同じ）
  - block.json の `editorScript` は PHP で登録したハンドル名を指す（block.json に版を持たせない）
- 版数を上げる・`dist` に push する作業は、エージェントではなく人が行う
- PUC は `dist` を見る。`.gitattributes` で開発用のファイルを配布物から外す。パターンは必ず先頭 `/` で固定する
- CI は原本（widget-shortcode-tools の `dist`）と byte 一致。PHPUnit は手元で回し、結果を PR に貼る
- 支援・依頼リンクはプラグイン一覧の行だけに置く（受託先のサイトの例外。etbs-notice-banner と同じ）
- 検証サイトは Local の `ai-wp-demo` に VK Blocks（無料版）と LiteSpeed Cache を入れて使う。シンボリックリンク設置でよい（`dirname( __FILE__, N )` を使わない）
- 導入先の表とサイト固有のひな形の置き場所は CLAUDE.md に書く

- 表示期間以外の条件（ログイン中だけ表示、など）
